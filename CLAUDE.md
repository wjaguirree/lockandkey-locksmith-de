## What this is

This directory is the **built, deployed output** of the Lock and Key Locksmith DE website (a locksmith serving Kent & Sussex County, Delaware). It is static HTML/CSS/JS meant to be served directly by Apache — there is no `package.json`, no build tool, and no `node_modules` here.

The site is generated by a separate `gen/` toolchain (e.g. `gen/redirects.mjs`, `gen/data.mjs`, `qa.mjs`) that is **not present in this directory**. Comments throughout `main.js` and `.htaccess` reference that generator (e.g. "Generated by gen/redirects.mjs", "DUPLICATED from gen/data.mjs BRAND.hours on purpose"). Treat this repo as the deploy target: edits made directly here will be overwritten if/when the site is regenerated from source, so prefer editing here only for direct hotfixes, and flag when a change should really happen upstream in the generator.

This directory is **not a git repository**.

## Structure

- `index.html`, `404.html` — top-level pages
- `main.js` — classic (non-module) script, defensively isolated per-feature via a `safe(name, fn)` wrapper so one failing init can't break the page. Includes open/closed status logic (Delaware/`America/New_York` time, hours duplicated from the generator's `BRAND.hours`) and an interactive SVG service-area map (city `<a>` dots/labels linking to `/service-areas/<city>/`).
- `reveal.js` — scroll-reveal + counting-stat animations. Governed by three rules stated in its header comment: nothing is hidden without JS (progressive enhancement — `.reveal` class is added by JS, never hidden by CSS alone), nothing above the fold is animated (protects LCP), and `prefers-reduced-motion` fully disables motion.
- `styles.css` — single global stylesheet
- `.htaccess` — Apache config: gzip, cache headers (HTML never cached, assets cached long + cache-busted via `?v=YYYYMMDD`), security headers, `www` → bare-domain redirect, forced trailing slash on directory URLs, and a generated 301-redirect block between `# >>> redirects` / `# <<< redirects` markers (do not hand-edit inside that block — it's regenerated by `gen/redirects.mjs`)
- `sitemap.xml`, `robots.txt`
- `assets/img/` — images

### Page types (each is a directory containing an `index.html`, giving pretty URLs like `/lock-rekey/`)

- **Service pages** (~28, top-level, e.g. `/lock-rekey/`, `/car-lockout/`, `/emergency-locksmith/`) — one per service offered.
- **Location pages** (`/service-areas/<city>-de/`, 51 total) — one per Delaware city/town served, featured on the interactive map in `main.js`.
- **Service × location pages** (`/<service>-in-<city>-de/`, ~1,400) — the combinatorial local-SEO pages, e.g. `/access-control-in-dover-de/`. Note some services use a longer slug in this combined form than in their top-level page (e.g. top-level `/automotive-locksmith/` vs. combined `/automotive-locksmith-services-in-<city>-de/`) — check `.htaccess`'s redirect block for the canonical slug mapping when in doubt.
- **Blog posts** (`/blog/<slug>/`)
- Standalone pages: `/about/`, `/faq/`, `/privacy-policy/`, `/terms/`, `/request/`, `/services/` (index), `/service-areas/` (index)

## Local development

Two equivalent ways to serve this site at `http://localhost:8090/` (port reserved for this project so it doesn't collide with other local sites):

- `npm start` — runs `npx http-server . -p 8090 -c-1` (no install needed, `package.json` exists only for this).
- `./serve.sh` (or `./serve.sh <port>`) — a dependency-free fallback wrapping `python3 -m http.server`.

Neither applies `.htaccess` rewrites/redirects (that's Apache-only), so trailing-slash/redirect behavior should still be verified against the real host before deploying.

## Working in this repo

- There's no build/lint/test command — verify changes by opening the HTML directly or serving the directory locally with `./serve.sh`.
- If you change the business hours, phone number, or other brand facts, they may be duplicated in multiple places (see the `main.js` `status` init) — search across `main.js`, `index.html`, and other pages for the same value rather than assuming a single source of truth, since the actual single source (`gen/data.mjs`) isn't in this directory.
- Because pages are static HTML with heavy duplication across ~1,400 service×location pages, prefer scripted/batch edits (`grep`/`sed` across matching files) over one-off manual edits when a change needs to apply site-wide, and double-check the edit against a few different page variants before assuming it applied correctly everywhere.
